## 失败详情

### C1.x / C5.x — 儿童 app 全流程 `AUTH` (阻塞性)
- **路由**: http://localhost:5174/child/
- **截图**: dogfood-output/child-login-page2.png
- **预期表现**: 儿童 app 应显示 PIN 选择页面 (emoji PIN grid), 支持 child 账号登录
- **当前错误表现**: :5174/child/ 清除 cookie+localStorage 后首次加载显示成人登录页 (username/password 表单), 而非儿童选择页; 后续导航均显示成人 dashboard 内容
- **初步判断**: 儿童 app 前端代码 `frontend/apps/child/src/api/index.ts:38` 注释 "child app has no auth pages" 并将未认证用户重定向到主 app 登录页。在 dev 模式下 (adult :5173 / child :5174 不同 origin), 儿童 app 无法共享成人 cookie, 导致所有儿童页面均显示成人登录或重定向到成人 app。**此问题阻塞 Area 1 (C1.1–C1.17) 和 Area 5 (C5.1–C5.10) 全部测试。**
- **建议**: 检查儿童 app 的 route guard 逻辑; 确认 dev 模式下儿童认证流程是否需要单独实现 (如 PIN-based child login)

### F.5 / C10.x — 访客页面 (register/join-family) 空白 `RENDER`
- **路由**: http://localhost:5173/register, http://localhost:5173/join-family
- **截图**: 无 (内容全空)
- **预期表现**: 访客应看到注册表单和加入家庭表单
- **当前错误表现**: bsk 新 session 访问 /register 和 /join-family 时, main 元素 contentLength=0, 页面空白。URL 正确停留在目标路由
- **初步判断**: bsk session 共享浏览器 profile, 成人 session 的 cookie 被带入新 session, 导致 route guard 认为用户已认证 (成人角色), 从而拒绝渲染访客页面。此问题可能仅影响 bsk 测试环境, 真实浏览器新开隐身窗口应正常
- **建议**: 在 bsk 测试访客流程前, 清除 cookie+localStorage 或改用独立浏览器 profile
