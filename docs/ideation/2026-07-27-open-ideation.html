1. Finance Hub Redesign + Dashboard 叙事化

执行已有 plan (2026-07-22)，将 Dashboard 从纯 stat cards 升级为"金融叙事仪表盘"：添加趋势注解（"你的净资产本月增长 12%，主要来自…"）、上下文提示条（"应急金可覆盖 2.3 个月支出，低于建议的 3-6 个月"）、接入闲置的 Treemap 组件。Finance Hub 成为完整列表入口，删除独立的 /assets、/liabilities、/wishes 页面。

Axis
财务管理 UX 设计
Basis
direct: Plan 已完成 (2026-07-22, 5天前)，implementation-ready；Dashboard 零图表；Treemap 组件已实现但 orphaned；当前分支 feat/main-app-ux-optimization
Rationale
这是最"新鲜"且可立即执行的方向。Plan 已设计好 Dashboard 作为 instrument panel + Finance Hub 作为列表入口的架构。在此基础上叠加叙事层（AI 生成的上下文注解），将 Dashboard 从"数据展示"提升为"财务顾问"。
Downsides
大范围 UX 重构影响现有用户习惯；叙事层需要可靠的 AI 生成质量，低质量注解比无注解更糟。

2. Proactive Weekly Finance Checkup (主动财务体检)

激活闲置的 scheduler_worker，每周自动生成"家庭财务体检报告"：应急金充足度、负债率、支出偏离、投资组合漂移。通过通知中心 + AI 聊天推送。用户从"有问题才问 AI"变成"AI 每周主动告诉你发现了什么"。

Axis
AI 交互 财务管理
Basis
direct: scheduler.py 已配置但零任务注册；multi-currency engine + AI skill system + 通知系统全部就绪，只需"接通"。finance_coach skill 已能生成叙事分析。
Rationale
每个新激活的用户每周产生一次 AI 触达 → 提高留存 → 更多数据录入 → 下次报告更准确。这是时间维度的飞轮：数据积累使 AI 洞察从"通用建议"进化为"家庭专属诊断"。Copilot Money 的 proactive spending summaries 是竞品验证信号。
Downsides
需要可靠的调度基础设施（Redis-backed）；低质量报告比无报告更糟；用户可能对推送感到疲劳。
Confidence
85%
Complexity
Medium
3. Capability Grid 2.0 — 能力即入口 (SkillRegistry-based)

将 AI 交互从 input-box-centric 转变为 capability-discovery-centric。用户通过能力网格发现和进入 AI 功能（财务体检、资产报告、愿望建议），每个能力有专属输入模式（结构化表单、资产选择器、确认对话框）。基于 SkillRegistry（CapabilityRegistry 的后继者，因 CapabilityRegistry 在 commit eb0c7851 中被删除）。

Axis
AI 交互
Basis
direct: CapabilityRegistry backend 已设计 (296行) 但在 commit eb0c7851 中被删除；SkillRegistry 是后继者。Dynamic input modes (structured, asset_selector, confirm_dialog) 从未实现。⚠️ 需基于 SkillRegistry 重新设计。
Rationale
从根本上改变用户发现 AI 价值的方式。不再是"我该问什么？"而是"我激活哪个能力？"。降低认知负荷，提高 AI 采用率。
Downsides
需要重建能力发现机制（前一个方案已被删除）；动态输入模式增加了前端复杂度。
Confidence
75%
Complexity
Medium
4. Family Knowledge Graph (跨会话知识沉淀)

从每次 AI 对话中提取结构化知识（"应急金应覆盖 3-6 个月支出"、"房贷月供不应超过收入 30%"）自动抽取为带引用的知识卡片，存储在家庭级 RAG 索引中。AI 回答时优先引用家庭知识库，形成"越用越懂你家"的效果。实现 deferred 的 citation chips 和 cross-session artifact registry。

Axis
AI 交互
Basis
direct: AI context builder 已存在，新数据领域只需新 builder 函数；cross-session artifacts + citation chips 均为 HIGH interestingness deferred 项。external: Securo 的 per-agent RAG knowledge base。
Rationale
家庭知识库是 Numina 独有的、不可迁移的资产，形成真正的 lock-in。每个对话产物成为未来对话的 context → 减少重复解释 → 回答更精准 → 用户更愿意深度提问 → 产出更多知识。知识维度上的飞轮。
Downsides
需要 RAG 基础设施（向量索引）；知识提取质量不确定；存储成本随对话量增长。
Confidence
70%
Complexity
High
5. Cash Flow Engine + Sankey 可视化

构建缺失的现金流基础设施：周期性交易模板（月薪、房租、订阅费）、基于规则的自动分类（参考 Firefly III）、Sankey 图可视化（收入 → 类别 → 支出）。这是预算、预测、异常检测、AI 支出建议、投资组合再平衡的共同底层基建。

Axis
财务管理
Basis
direct: evidence-learnings 明确标注 "no budget/spending plan feature" + "no recurring transaction tracking" 是核心 gap。Dashboard/FinanceHub 零图表。external: Firefly III rules engine；D3 d3-sankey plugin。
Rationale
现金流引擎是功能维度的飞轮：一旦有时序收支数据 → AI 可做支出预测（Copilot Money）→ 可做预算建议 → 可做异常检测。Sankey 图一个组件可用于多个场景（现金流、资产配置、负债偿还路径）。
Downsides
工程量最大的方向之一；需要新的数据模型（recurring transactions）；Sankey 在移动端可能过小。
Confidence
75%
Complexity
High
6. 儿童财商生态 (Progression + Opportunity-Cost + Teacher Mode + Governance)

四个儿童方向的合方向：(1) 渐进式财商等级 Lv1记账→Lv2储蓄→Lv3预算→Lv4投资→Lv5决策；(2) 机会成本 peek — 长按愿望看"如果花在这里，其他愿望推迟N天"；(3) 孩子当老师 — 孩子的财务推理生成家长可见的"素养周报"；(4) 渐进式治理 — 孩子从¥200晚餐选择升级到¥2000家庭储蓄分配。

Axis
儿童财商
Basis
direct: 儿童系统已有深度但碎片化的 gamification 基础设施 (star coins, chores, wishes, celebration v2)。Cross-wish bundle plan 含 opportunity-cost peek。external: Greenlight/Step progressive missions 是儿童金融 app 核心留存机制；Vygotsky ZPD 理论支持"教学即学习"。
Rationale
等级系统是内容维度的飞轮：孩子升级 → 解锁新能力 → 家长看到成长 → 更愿意设置新任务。同时是基础设施：Lv4 家庭银行需要利息引擎（可复用于 D8 区间收益率）；Lv3 预算需要收支预测（可复用于成人预算）。解决"孩子长大就不用了"的留存问题。
Downsides
渐进式治理涉及真实财务权限委托，需要仔细的安全设计；素养周报的 AI 生成质量需保证。
Confidence
75%
Complexity
High

8. Financial Health Scorecard (财务健康度评分)

多维度评分系统：应急金充足度、负债健康度、投资多元化、储蓄率、保险覆盖度，各 0-100 分。加权综合得分 + letter grades (A/B/C/D) + 同龄对比（"你的应急金充足度超过 78% 的同龄家庭"）。Dashboard 首页展示 scorecard。

Axis
财务管理 UX 设计
Basis
external: PortfolioPilot report cards 是 2025-2026 dashboard 创新趋势。Multi-currency engine 可处理跨币种资产。reasoned: 评分系统将模糊的"我财务情况怎么样"量化为可操作数字。
Rationale
游戏化财务改善：用户看到低分项 → 采取行动（录入更多数据、调整资产结构）→ 得分提升 → 形成 engagement flywheel。Scorecard 本身也是 AI 建议的自然入口。
Downsides
评分模型需要领域专家校准；同龄对比需要数据基础（C23 Family Census 被否决后可用匿名统计替代）。
Confidence
70%
Complexity
Medium
9. Zero-Touch Chore Verification (零触碰家务验证)

利用现有 vision model 基础设施 (U11 vision PDF, 98% 准确率) 自动验证家务完成。孩子拍摄清洁后的房间照片 → vision model 确认 → 星币自动到账。消除家长审批瓶颈。

Axis
儿童财商 AI 交互
Basis
direct: U11 vision model 已处理扫描 PDF (98% 准确率)；vision-test stub 存在。家长审批流程已建。
Rationale
移除家长作为审批瓶颈，增加孩子自主性，减少家长疲劳。将 vision 基础设施从"报告生成"扩展到"行为验证"，开辟新的 AI 应用场景。
Downsides
Vision 模型判断"房间是否干净"的主观性；误判可能引发亲子冲突；需要 fallback 到家长审批。

10. Ambient Finance + Per-Asset AI Advocates (环境财务 + 资产守护者)

两个互补方向的合并：(1) 无屏幕财务推送 — 晨间通知("本周净资产 +2.3%")、阈值提醒、月度 AI 语音摘要。Dashboard 仅作为 deep-dive escape hatch。(2) 每个重要资产有专属监控 agent — 房产追踪市场比较、车辆追踪折旧、投资组合追踪漂移。Dashboard 变为"家庭议会"视图。

Axis
AI 交互 财务管理
Basis
direct: 通知系统 (channels, subscriptions, reminders) 完全确认；FinanceCoachCard 已能生成叙事摘要。reasoned: Push-based inverts activation energy — 用户不必主动打开 app。Per-asset agents 将"你可以问资产"变为"你的资产被守护着"。
Rationale
最大的留存风险不是功能缺失，而是用户不参与。Push-based 环境层以 1% 注意力成本传递 80% 仪表盘价值。Per-asset agents 创造主动监控的全新价值主张。
Downsides
推送频率和内容的平衡困难；per-asset agents 需要大量计算资源；需要外部数据源才能真正有价值（市场数据、房产估值）。
Confidence
60%
Complexity
High

Cross-Cutting Synthesis

这个方向与 #2 Proactive Checkup 形成"主动 AI 顾问"系统 (Synthesis S1)：scheduler 运行周度扫描 + per-asset agents 运行持续监控 + push 层负责交付。三者合一是 Numina 从"资产追踪器"到"家庭财务顾问"的核心转型路径。
