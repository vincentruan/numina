# Ideation: 智能财务管家 — AI资产管理Agent模块

## Codebase Context

**项目形态：** Python 3.13 FastAPI后端 + Vue 3 / Vant 4 移动H5前端，Docker Compose部署，家庭隔离数据模型（family_id全局作用域）。

**现有杠杆点：**
- `AssetSnapshot` 模型已提供每日净资产时间序列
- Dashboard聚合端点（overview / allocation / trend / top-assets / daily-cost / low-usage / returns）已产出AI所需的全部原始信号
- Asset模型已有 `expected_lifespan_days`、`annual_maintenance_cost`、`usage_frequency`、`sell_channel` 等字段，但完全被动
- `CacheBackend` 抽象（get/set/increment）可复用于agent会话状态和LLM响应缓存
- `security_log` 服务已建立结构化审计日志模式，AI操作应接入
- 全局限速中间件（100 req/min）必须覆盖新的 `/api/v1/ai/` 端点
- User模型已有 `role`（admin/member）字段，可直接用于AI能力开关的权限控制

**关键空白：**
- 无AI/LLM集成层（完全绿地）
- 无特性开关机制（per-family admin toggle）
- 无后台任务调度器（定期报告需要）
- 无PII脱敏管道（发送给LLM前必须建立）
- `expected_lifespan_days` / `usage_frequency` 字段填写率低，影响部分功能的数据质量

**机构知识（来自docs/solutions/）：**
- Redis fail-fast策略：若 `CACHE_BACKEND=redis`，agent会话状态不得静默降级为内存缓存
- 安全审计：AI agent读取家庭资产数据的操作应通过 `security_log` 记录
- 限速：新AI端点不得加入全局限速豁免名单；建议对LLM调用设置更严格的per-user限制

## 前提基础设施（非功能特性，必须优先建设）

### 0. AI管理员开关与数据脱敏管道

**描述：** 独立Python模块（`agent/`），包含：
1. `family.ai_enabled` 字段（per-family admin toggle，通过 `PUT /api/v1/ai/config` 配置）
2. 可复用的脱敏管道：将资产名称替换为类别标签、将精确金额替换为区间/比率、剥离成员姓名和账号信息
3. Anthropic SDK 或 pydantic-ai 封装层，统一LLM调用接口
4. 所有AI端点的 `ai_enabled` 守卫中间件

**为何必须优先：** Numina的核心价值主张是"隐私优先、自托管"。没有硬性管理员开关和经过验证的脱敏层，任何AI功能都不能负责任地发布。

**复杂度：** Medium | **状态：** Prerequisite

## 排名后的功能创意

### 1. 家庭资产体检报告（旗舰功能）

**描述：** 定期（月度）或按需生成的AI健康报告，综合净资产趋势、资产集中度风险、负债压力比率、闲置资产拖累、流动性比率，输出带叙事的结构化报告。报告以H5卡片组形式展示，支持截图分享。脱敏后的聚合数据（比率+区间，非精确值）发送给LLM生成叙事，报告实体存储于新的 `ai_reports` 表。

**理由：** 家庭积累了数据但缺乏解读层。体检报告将被动记账转化为主动感知，是个人理财应用中用户最期待的单一功能。所有原始信号（snapshot、allocation、trend、daily-cost、low-usage、returns）已存在，AI只需读取并叙述。

**劣势：** 需要新的 `ai_reports` 表和定时任务基础设施；报告质量依赖数据完整性，新家庭数据稀少时报告价值有限。

**置信度：** 92% | **复杂度：** Medium | **状态：** Unexplored

---

### 2. 智能资产录入助手（数据质量飞轮）

**描述：** 两层能力：
- **对话式录入：** 用户用自然语言描述资产（"我买了一台MacBook Pro，花了14999，主要用来工作"），AI解析为结构化payload，预填表单，用户确认后提交。
- **字段智能补全：** 基于资产名称+类别，AI建议 `expected_lifespan_days`、`annual_maintenance_cost`、`usage_frequency`、类别和标签的默认值（"iPhone 15 Pro → 数码，预期寿命1095天，维护成本约0"）。

**理由：** 这是一个数据质量飞轮：当前表单有15+字段，用户普遍跳过可选字段，导致老化预警（#3）和处置建议（#5）功能对大多数资产失效。解决录入摩擦同时修复了下游数据质量问题，是杠杆效应最强的单一改进。

**劣势：** LLM结构化提取偶尔幻觉字段值，必须有确认步骤；对话式录入需要前端新增聊天组件。

**置信度：** 88% | **复杂度：** Medium | **状态：** Unexplored

---

### 3. 固定资产老化预警与换购建议

**描述：** 监控设置了 `expected_lifespan_days` 的实物资产，计算剩余使用寿命，生成换购时机建议（含估算残值窗口和"现在卖vs继续用"分析）。交叉参考 `usage_frequency` 和 `annual_maintenance_cost` 优先排序哪些资产正进入"维修成本>资产价值"区间。以Dashboard推送卡片形式展示，而非独立页面。

**理由：** `expected_lifespan_days`、`annual_maintenance_cost`、`usage_frequency` 字段已存在但完全被动，仅用于日均成本计算。家庭没有主动信号提示何时该换车或换家电。此功能将被动字段转化为前瞻性提示。

**注意：** 此功能依赖 #2（录入助手）提升字段填写率。独立部署时价值有限，与 #2 组合后价值倍增。

**劣势：** 强依赖 `expected_lifespan_days` 字段，用户填写率低时覆盖面窄；需要 #2 先行建设以解决数据质量问题。

**置信度：** 78% | **复杂度：** Low-Medium | **状态：** Unexplored

---

### 4. 负债优化建议

**描述：** 基于家庭全部活跃负债（房贷、车贷、信用卡、个人贷款）和可用流动资产，AI建模多种还款策略（雪崩法、滚雪球法、混合法），推荐最小化总利息支出同时保留流动性缓冲的还款顺序。输出月度还款计划时间线组件，并支持"如果收入下降20%，哪些负债最先无法偿还"的压力测试场景。

**理由：** 多负债家庭默认做出次优还款决策（到处还最低额）。一个具体的、个性化的计划加上预计节省金额具有高度激励性和直接可操作性。Liability模型已有 `remaining_amount`、`interest_rate`、`monthly_payment`——计算是确定性数学，LLM仅添加叙事解释。

**劣势：** 仅对有多笔负债的家庭有价值；单笔负债家庭使用率低；`interest_rate` 字段可能未填写。

**置信度：** 82% | **复杂度：** Medium | **状态：** Unexplored

---

### 5. 低效资产处置建议

**描述：** 基于现有的低使用率资产列表（`usage_frequency = 'rarely'` 或 `'idle'`），AI生成每项资产的具体处置建议：推荐出售渠道（闲鱼/转转/回收站）、估算转售价格区间、基于类别情感价值（珠宝vs电子产品）和日均成本拖累的"保留vs出售"评分。输出优先级"清仓清单"。

**理由：** 低使用率Dashboard端点已识别问题资产，但用户面对列表无从行动，因为下一步不明确。AI将被动列表转化为具体行动队列，附带渠道特定指导。`sell_channel` 字段已存在于Asset模型，表明此工作流已被预期但从未自动化。

**注意：** 同样依赖 `usage_frequency` 字段填写率，与 #2 组合后价值倍增。

**劣势：** 依赖 `usage_frequency` 数据质量；"把闲置相机卖到闲鱼"是用户已知的建议，AI增量价值在于量化不行动的成本。

**置信度：** 75% | **复杂度：** Medium | **状态：** Unexplored

---

### 6. 自然语言资产问答助手

**描述：** H5界面中嵌入的持久聊天输入，家庭成员可用自然语言提问关于自己数据的问题——"我们家净资产比去年同期涨了多少？"、"哪个成员的资产最多？"、"我的车还值多少钱？"——Agent将问题翻译为对家庭脱敏数据快照的结构化查询，返回直接答案，而非重定向到Dashboard。

**理由：** 非主要用户（配偶、老人）很少导航到正确的Dashboard面板。聊天界面将访问门槛降至零——任何家庭成员都能在不知道去哪里看的情况下得到答案。这是可能的最高杠杆单一界面改变。

**实现建议：** 不要构建开放式聊天——构建固定意图路由器（NL输入），支持有限的查询类型，优雅降级处理不支持的查询。

**劣势：** 意图分类和歧义查询处理复杂；用户提出数据无法回答的问题时会损失信任；需要严格的支持查询类型范围。

**置信度：** 80% | **复杂度：** High | **状态：** Unexplored

---

### 7. 资产分配漂移检测与再平衡提醒

**描述：** 将家庭当前资产配置（来自allocation端点）与用户定义或AI建议的目标配置进行比较，检测超过可配置阈值的漂移，生成平实语言的再平衡建议。每周运行，仅在漂移超过阈值时推送通知卡片。

**理由：** 金融资产配置在牛市后静默漂移。一个从目标60%金融/40%实物漂移到80/20的家庭不会注意到，直到市场下行。当前没有机制检测或响应这种漂移。

**注意：** 此功能仅在家庭设置了目标配置后才有实质价值。需要先建设简单的目标配置UI；没有目标配置，此功能退化为现有饼图的劣化版本。

**劣势：** 需要用户主动设置目标配置（他们可能不会）；仅对有实质金融资产组合的家庭相关。

**置信度：** 70% | **复杂度：** Low-Medium | **状态：** Unexplored

## 跨切合成洞察

**数据质量飞轮（#2 + #3 + #5）：** 这三个功能形成一个自我强化的循环。#2（录入助手）通过AI辅助补全提升 `expected_lifespan_days` 和 `usage_frequency` 的填写率；这直接解锁了#3（老化预警）和#5（处置建议）对更多资产的覆盖面。单独建设#3或#5而不先建设#2，等于在稀疏数据上建功能。**建议：将#2作为#3和#5的前置依赖。**

**AI能力分层架构：** 建议将AI能力分为三层：
1. **被动层**（无需LLM）：分配漂移检测、老化阈值计算——纯规则逻辑，AI仅添加叙事
2. **主动层**（按需LLM）：体检报告、负债优化、问答助手——用户触发，单次LLM调用
3. **对话层**（多轮LLM）：录入助手——多轮交互，需要会话状态管理

## 推荐建设顺序

```
Phase 0: 基础设施
  └── AI管理员开关 + 脱敏管道 + Anthropic SDK封装

Phase 1: 旗舰功能（高价值，低数据依赖）
  ├── 家庭资产体检报告（#1）
  └── 智能资产录入助手（#2）— 数据质量飞轮启动

Phase 2: 数据驱动功能（依赖Phase 1积累的数据质量）
  ├── 固定资产老化预警（#3）
  ├── 负债优化建议（#4）
  └── 低效资产处置建议（#5）

Phase 3: 高级交互（复杂度高，依赖前两阶段数据）
  ├── 自然语言问答助手（#6）
  └── 资产分配漂移检测（#7）
```
