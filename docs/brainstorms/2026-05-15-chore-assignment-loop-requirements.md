# 任务管理闭环 — 需求文档

**日期：** 2026-05-15
**状态：** 草稿

---

## 背景

当前任务系统支持两种模板类型：
- **assigned**：指定孩子，每人一个实例
- **pool**：无主任务，`child_user_id == family_id`，任何孩子都可以完成

现有问题：
1. 家长在宝贝页任务列表看不到任务的认领/指派状态
2. 家长无法对单个实例进行指派、改派、作废操作
3. 子端只能看到自己的任务，看不到 pool 任务，无法认领
4. 子端没有"放弃"流程，认领后只能完成或等待

---

## 目标

1. **家长侧**：任务列表展示指派状态，支持指派、改派、作废操作
2. **子端**：展示无主任务 + 指派给自己的任务，支持认领和放弃
3. **放弃引导**：放弃时展示激励文案（积分 + 心愿进度），降低放弃率

---

## 用户故事

### 家长

- 作为家长，我想在任务列表中看到每个 pool 任务是否已被认领（以及被谁认领），以便了解任务进展
- 作为家长，我想将某个 pool 任务硬指派给某个孩子，使其他孩子不可见/不可认领
- 作为家长，我想对已指派的任务改派给另一个孩子
- 作为家长，我想作废某个任务实例（今天不做了），模板保留，下次周期正常生成

### 孩子

- 作为孩子，我想在任务页看到所有无主任务和指派给我的任务
- 作为孩子，我想认领一个无主任务，让它变成我的任务
- 作为孩子，我想放弃一个已认领/指派给我的任务，但放弃前我希望看到放弃的代价（积分损失 + 心愿影响）
- 作为孩子，如果我确认放弃，任务回到无主状态，其他孩子可以认领

---

## 功能范围

### 1. 家长侧：任务列表增强（BabyPage 任务 Tab）

**展示变化：**
- Pool 任务卡片新增"认领人"信息：
  - 已认领/指派：展示孩子头像 + 姓名
  - 未认领：展示"无主"标签
- 每张任务卡片底部增加操作按钮（钢琴键风格，与待审批卡片一致）：
  - **未认领任务**：`指派` 按钮
  - **已认领/指派任务**：`改派` + `作废` 按钮
  - **已完成/审批中任务**：不展示操作按钮（状态已终态）

**指派/改派流程：**
- 点击`指派`或`改派`，弹出底部弹窗，展示家庭成员列表（仅 child 角色）
- 选择孩子后确认，调用指派 API
- 指派后该实例的 `child_user_id` 改为目标孩子 ID（硬指派语义）

**作废流程：**
- 点击`作废`，弹出确认对话框
- 确认后删除该实例（软删除或硬删除，见后端设计）
- 下次周期（明天/下周）正常生成新实例

### 2. 子端：任务列表重构（ChildTasksPage + ChildHomePage）

**任务来源变化：**
- 当前：`GET /child/chores?date=` 只返回自己的实例
- 新增：同时返回 pool 任务（`child_user_id == family_id` 且未被硬指派）
- 新增：返回硬指派给自己的任务

**任务卡片状态与操作：**

| 任务类型 | 状态 | 操作按钮 |
|---------|------|---------|
| Pool（无主） | available | `认领` |
| Pool（已认领/指派给我） | available | `完成` + `放弃` |
| Pool（已认领/指派给我） | pending_approval | 状态标签（待审批） |
| Assigned（指派给我） | available | `完成` + `放弃` |
| 任意 | approved | 状态标签（已完成） |
| 任意 | rejected | 状态标签（已退回） |

**认领流程：**
- 点击`认领`，调用认领 API
- 成功后任务变为"指派给我"状态，展示`完成` + `放弃`按钮
- 乐观更新本地状态

**放弃流程（关键体验）：**
1. 点击`放弃`，弹出底部弹窗（非简单确认框）
2. 弹窗内容：
   - 标题：「确定放弃这个任务吗？」
   - 积分提示：「完成可获得 **{coin_reward}** ⭐」
   - 心愿激励（如有高优先级心愿）：「距离「{wish_name}」还差 **{remaining}** ⭐，完成这个任务又近一步了 🌟」
   - 两个按钮：`继续完成`（主按钮，品牌色）+ `放弃任务`（次按钮，灰色）
3. 确认放弃后：
   - 调用放弃 API，任务回到无主状态
   - 家长收到静默通知（不打扰孩子）
   - 本地移除该任务卡片（或刷新列表）

**首页今日任务（ChildHomePage）：**
- 同步展示 pool 无主任务和指派给自己的任务
- 认领/放弃操作与任务页一致（复用逻辑）

### 3. 后端 API 变更

#### 新增端点

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| `POST` | `/family/chore-instances/{id}/assign` | owner/adult | 指派/改派给某孩子 |
| `DELETE` | `/family/chore-instances/{id}` | owner/adult | 作废实例 |
| `POST` | `/child/chores/{id}/claim` | child | 认领 pool 任务 |
| `POST` | `/child/chores/{id}/abandon` | child | 放弃已认领/指派任务 |

#### 修改端点

- `GET /child/chores?date=` — 同时返回 pool 任务（无主 + 指派给自己）

#### 数据模型变更

`ChoreInstance` 新增字段：
- `assigned_by_user_id: int | None` — 记录是谁做了硬指派（区分"认领"和"家长指派"）
- `claimed_at: datetime | None` — 认领时间

**指派语义实现：**
- 硬指派：将 `child_user_id` 从 `family_id` 改为目标孩子 ID，设置 `assigned_by_user_id`
- 改派：同上，更新 `child_user_id` 和 `assigned_by_user_id`
- 认领：将 `child_user_id` 从 `family_id` 改为认领孩子 ID，`assigned_by_user_id` 为 null（区分认领 vs 指派）
- 放弃：将 `child_user_id` 改回 `family_id`，清空 `assigned_by_user_id` 和 `claimed_at`

**作废语义：**
- 硬删除该实例（`DELETE`）
- 唯一约束解除，下次周期 `get_or_create_instances` 正常重建

## 非目标

- 不支持孩子主动创建任务
- 不支持多孩子同时认领同一 pool 任务（先到先得，认领即锁定）
- 不支持家长批量指派
- 不修改 assigned 模板的指派逻辑（模板级别已有 assignees）

---

## 成功标准

- [ ] 家长在宝贝页任务 Tab 能看到每个 pool 任务的认领状态
- [ ] 家长可以指派/改派/作废任务实例
- [ ] 孩子在任务页能看到无主任务和指派给自己的任务
- [ ] 孩子可以认领无主任务
- [ ] 孩子放弃时看到积分 + 心愿激励文案
- [ ] 放弃后任务回到无主状态，家长收到通知
- [ ] 所有操作有乐观更新，失败时回滚

---

## 技术约束

- 认领操作需要并发安全（两个孩子同时认领同一任务）：使用数据库唯一约束 + 乐观锁或 `SELECT FOR UPDATE`
- 放弃激励文案需要子端能获取当前最高优先级心愿（已有 `listChildWishes` API）
- 新增字段需要 Alembic migration
- 所有新 UI 字符串需同步更新 `zh-CN.ts` 和 `en-US.ts`
