# AI 负债优化顾问

## Problem Frame

家庭有多笔负债（房贷、车贷、信用卡、个人贷款）时，默认决策是"到处还最低额"——这是利息损失最大的策略。Numina 已存储 `remaining_amount`、`monthly_payment`、`interest_rate`、`end_date` 等字段，具备计算最优还款策略的全部数据基础，但目前只是被动展示，没有任何推理层。

本功能分两层：
1. **Dashboard 摘要卡片** — 一目了然掌握负债全貌和核心建议
2. **AI 负债顾问专属页面** — 多策略对比 + 自然语言问答，像有一个财务顾问随时解答

```
Dashboard 负债摘要卡片
    │  点击"查看详细建议"
    ▼
AILiabilityAdvisorPage
    ├── 策略对比区（雪崩 / 滚雪球 / 混合）
    ├── 推荐还款顺序列表
    ├── 预设问题快捷按钮
    └── 自由输入问答框
              │
              ▼
        调用 AI 问答接口
        （携带脱敏负债快照作为上下文）
              │
              ▼
        返回回答 + 追加到对话历史
```

## Requirements

**AI 基础设施前提（依赖 Phase 0）**

- R0. 依赖 `docs/brainstorms/2026-04-10-001-ai-health-report-requirements.md` 中 R0-R6 的基础设施。

**后端：策略计算**

- R1. `GET /api/v1/ai/liability-advice` 返回当前家庭的负债优化建议，包含：
  - 三种策略的对比数据（雪崩法 / 滚雪球法 / 混合法）
  - 推荐策略及理由
  - 各负债的推荐还款优先级排序
  - 总利息节省估算（推荐策略 vs 当前最低还款）
- R2. 利率处理规则：
  - 有 `interest_rate` 字段的负债：使用精确值计算
  - `interest_rate` 为 NULL 的负债：按类别默认利率估算（`mortgage`=4%、`car_loan`=6%、`credit_card`=18%、`personal_loan`=12%、`other`=8%）
  - 使用估算利率的负债在响应中标记 `rate_estimated: true`，前端展示"~"前缀提示用户
- R2a. `monthly_payment` 为 NULL 的负债处理规则：
  - 该负债仍参与策略排序（按利率/余额排序不依赖月供）
  - 还清时间和总利息计算中，使用 `remaining_amount / 12` 作为估算月供，并在响应中标记 `payment_estimated: true`
  - 前端在该负债条目旁展示"月供估算"标注，提示用户补充实际月供数据
- R3. 三种策略定义：
  - **雪崩法**：优先还利率最高的负债（最小化总利息）
  - **滚雪球法**：优先还余额最小的负债（最大化心理激励）
  - **混合法**：家庭默认货币余额 < 10,000 CNY 等值的负债按滚雪球，其余按雪崩（平衡心理与数学最优）；混合法阈值始终以 CNY 为基准，多货币场景下按当前汇率换算后比较
- R4. 策略计算为纯确定性数学，不调用 LLM；LLM 仅用于生成推荐理由的叙事文本（中文，50-100字）和问答回答。
- R5. 响应结果缓存 1 小时（`CacheBackend`）；以下任一操作发生时主动失效缓存：还款记录（`PUT /liabilities/{id}/payment`）、新增负债、删除负债、编辑负债（`PUT /liabilities/{id}`，含利率/月供/余额/状态变更）。
- R6. 脱敏要求：发送给 LLM 的数据包含负债类别、`remaining_amount`（金额区间）、`interest_rate` 或估算利率、`monthly_payment`（金额区间）、`end_date`（年月精度）；不包含负债名称、机构名称、精确金额。
- R7. 当家庭活跃负债数量为 0 或 1 时，`GET /api/v1/ai/liability-advice` 返回 `{"insufficient_data": true, "message": "需要至少2笔活跃负债才能生成优化建议"}`，前端展示引导提示。
- R7a. 多货币负债转换：所有负债的 `remaining_amount` 和 `monthly_payment` 在策略计算前统一转换为家庭默认货币；若某货币汇率数据不存在（`ExchangeRateService` 回退到 1:1），在响应中标记 `currency_rate_estimated: true` 并在前端展示"含汇率估算"警告，提示计算结果可能不准确。

**后端：问答接口**

- R8. `POST /api/v1/ai/liability-advice/chat` 接收 `{"question": str, "conversation_history": [...]}` ，以家庭脱敏负债快照为上下文，调用 LLM 返回回答。**此接口不受活跃负债数量限制**——当家庭负债数量不足 2 笔时，快照为空或仅含 1 条记录，LLM 以通用负债管理知识回答；前端在 `insufficient_data == true` 时在问答区顶部展示提示"当前数据不足，以下为通用建议"。
- R9. `conversation_history` 最多携带最近 10 轮对话（1 轮 = 1 条用户消息 + 1 条 AI 回复，共 20 条消息）；超出时截断最早的轮次，避免 token 超限。
- R10. 问答接口 per-family 限速：每小时最多 30 次（问答频率高于报告生成）。
- R11. 对话历史仅存储在前端（不持久化到数据库）；刷新页面后对话重置。

**前端：Dashboard 摘要卡片**

- R12. `DashboardPage.vue` 在负债区域新增"负债优化"摘要卡片，仅当 `ai_enabled == true` 且活跃负债 ≥ 2 时展示。
- R13. 摘要卡片展示：推荐策略名称、总利息节省估算（"采用雪崩法可节省约 ¥XX,XXX 利息"）、推荐还款顺序前两项（负债类别 + 优先级序号）、"查看详细建议"按钮。
- R14. 利息节省估算有估算利率时显示"约 ¥XX,XXX（含估算利率）"，提示数据可能不精确。

**前端：AI 负债顾问页面**

- R15. 新增 `AILiabilityAdvisorPage.vue`，从 Dashboard 摘要卡片"查看详细建议"按钮进入，也可从 `LiabilityListPage.vue` 顶部入口进入。
- R16. 页面分三个区域（垂直滚动）：
  - **策略对比区**：三种策略的 Tab 切换（雪崩 / 滚雪球 / 混合），每个 Tab 展示：总利息、还清时间、推荐还款顺序列表（负债类别 + 月供建议 + 预计还清月份）
  - **推荐区**：高亮展示推荐策略 + AI 叙事理由
  - **问答区**：预设问题快捷按钮 + 对话历史 + 自由输入框
- R17. 预设问题快捷按钮（固定 5 个）：
  - "哪笔负债应该优先还？"
  - "如果每月多还 ¥2000 能省多少利息？"
  - "我的负债压力大吗？"
  - "信用卡和房贷哪个更紧急？"
  - "什么时候能还清所有负债？"
- R18. 点击预设问题按钮后，问题文字填入输入框并自动发送，等同于用户手动输入。
- R19. 对话区展示气泡样式（用户消息右对齐蓝色，AI 回答左对齐灰色），AI 回答时显示打字动画（流式输出或 loading 状态）。
- R20. 输入框底部固定，支持多行输入（最多 200 字），发送按钮在输入内容非空时激活。
- R21. 当 `insufficient_data == true` 时，顾问页面展示空状态插图 + "至少需要 2 笔活跃负债才能使用此功能"提示，问答区仍可使用（用户可咨询一般性负债管理问题）。

## Success Criteria

- 有 ≥ 2 笔活跃负债的家庭能看到 Dashboard 摘要卡片和完整策略对比。
- 三种策略的利息计算结果可通过手工验算验证（纯数学，无 LLM 参与）。
- 使用估算利率的负债在 UI 中有明确标识（"~"前缀或说明文字）。
- `monthly_payment` 为 NULL 的负债在 UI 中有"月供估算"标注。
- 问答响应时间 < 8 秒（P90）。
- 对话历史在同一页面会话内保持连贯，刷新后重置。
- `ai_enabled == false` 时 Dashboard 摘要卡片不渲染，顾问页面不可访问（路由守卫返回 Dashboard）。
- 汇率数据缺失时，计算结果页面展示"含汇率估算"警告而非静默返回错误数值。

## Scope Boundaries

- 不包含还款计划的日历视图或月度时间线图表（首版用列表展示）。
- 不包含"额外还款模拟器"的独立 UI（"每月多还 ¥2000"类问题通过问答回答，不做专属计算器）。
- 不包含对话历史的持久化（刷新重置，不存数据库）。
- 不包含跨货币负债的策略计算——多货币负债统一转换为家庭默认货币后计算，汇率使用当前汇率快照；汇率缺失时回退并标记（见 R7a）。
- 策略计算不考虑提前还款违约金（首版假设无违约金，在 UI 中注明）。
- 问答范围不限于家庭数据——用户可咨询一般性负债管理知识，AI 以家庭数据为上下文但不强制限制话题。

## Key Decisions

- **数学计算 + AI 叙事分离** — 策略计算用确定性数学（避免 LLM 幻觉金额），LLM 只生成叙事和回答问答；两者职责清晰。
- **无利率时按类别估算** — 覆盖面最广；估算值在 UI 中明确标识，用户知情。
- **无月供时按余额/12估算** — 保证所有活跃负债都能参与策略计算；估算值在 UI 中标注，引导用户补充数据。
- **对话历史不持久化** — 负债数据敏感，不在数据库存储对话内容；前端内存存储足够满足单次会话需求。
- **预设问题 + 自由输入** — 降低冷启动门槛；预设问题覆盖最常见场景，自由输入满足个性化需求。
- **策略计算结果缓存 1 小时** — 计算结果稳定，无需每次重算；负债任何变更（含编辑）时主动失效保证数据新鲜。
- **问答接口不受负债数量门控** — 用户在数据不足时仍可咨询通用知识，降低功能空白感；前端通过提示文字区分"完整建议"与"通用建议"两种状态。

## Dependencies / Assumptions

- 依赖 Phase 0 基础设施（`agent/` 模块、`ai_enabled` 开关、`CacheBackend`）。
- `interest_rate` 字段在 Liability 模型中已存在但为可选，估算利率作为后备。
- `monthly_payment` 字段在 Liability 模型中已存在但为可选，缺失时使用 `remaining_amount / 12` 估算。
- 多货币负债转换依赖现有 `ExchangeRateService.convert()`，汇率使用调用时最新值；`get_rate()` 在无数据时回退到 1:1，此回退需在响应中透明标记。
- 假设家庭平均活跃负债 2-5 笔，策略计算复杂度可控（O(n log n)）。
- 问答上下文构造：每次调用携带脱敏负债快照（类别+区间金额+利率+月供）+ 最近 10 轮（20 条消息）对话历史。
