# DeerFlow vs Numina AI Chat State Machine

State transition diagram and lifecycle documentation for AI chat interactions.

## State Definitions (Exact Names)

### Core States

| State | Display | Trigger | Next States |
|-------|---------|---------|-------------|
| **welcome** | Welcome prompt, suggestions visible | Navigate to `/ai/chat` with no `sessionId` | idle, submitting |
| **idle** | Input enabled, no active stream | After completed/failed, or on page load with existing session | submitting |
| **submitting** | "发送中..." indicator, input disabled | User clicks send / Enter key | streaming, failed |
| **streaming** | AI response progressive render, input disabled | HTTP 200, NDJSON stream starts | completed, failed, stopping |
| **stopping** | Partial response preserved, input re-enabled | User clicks stop button | completed (partial) |
| **completed** | Full response rendered, action buttons visible | `capability.end` event received | idle, submitting (regenerate) |
| **failed** | Error message visible, retry button available | HTTP error / SSE error / timeout | idle (retry), submitting |
| **reconnecting** | Reconnection indicator, preserving partial response | SSE connection lost during streaming | streaming, failed |

## Lifecycle Variables

### threadId (Session ID)

| Lifecycle | Description |
|-----------|-------------|
| **Creation** | Generated by backend on first message submission, returned in response |
| **Storage** | Stored in URL (`?sessionId=xxx`), Vue reactive state, localStorage |
| **Persistence** | Persists across page reloads, used for history loading |
| **Update** | Can be updated via URL navigation or "新对话" button (sets to null) |
| **Usage** | Sent in all subsequent API requests for session continuity |

```typescript
// threadId lifecycle in Vue component
const threadId = ref<string | null>(null)

// On page load: check URL
threadId.value = route.query.sessionId as string || null

// On first response: update from API
threadId.value = response.threadId
router.replace({ query: { sessionId: threadId.value } })

// On new chat: reset
threadId.value = null
router.replace({ query: {} })
```

### runId (Request/Execution ID)

| Lifecycle | Description |
|-----------|-------------|
| **Creation** | Generated by backend for each message submission, returned in SSE stream |
| **Scope** | Per-message scope (one runId per user message) |
| **Usage** | Used for regenerate, stop/cancel, and error tracking |
| **Reset** | New runId generated for each new message or regenerate |

```typescript
// runId lifecycle in Vue component
const runId = ref<string | null>(null)

// On submission start: null (pending assignment)
runId.value = null

// On SSE stream start: assigned from event
// Event: { type: 'phase.connecting', task_id: 'xxx', ... }
runId.value = event.task_id

// On completed/failed: preserved for regenerate reference
// Regenerate uses runId to identify which response to regenerate

// On idle: can be cleared or preserved for reference
```

### AbortController (Stream Cancellation)

| Lifecycle | Description |
|-----------|-------------|
| **Creation** | New instance created when user submits message (`new AbortController()`) |
| **Active** | Signal passed to fetch/SSE connection, controller stored in state |
| **Abort** | `abort()` called when user clicks stop button or connection times out |
| **Cleanup** | Controller set to `null` after stream completes or aborts |
| **Recreation** | New controller created for each new submission |

```typescript
// AbortController lifecycle in Vue component
const abortController = ref<AbortController | null>(null)

// On submission:
abortController.value = new AbortController()
const signal = abortController.value.signal

// SSE/fetch with signal:
fetch('/api/chat/stream', { signal })

// On stop button click:
if (abortController.value) {
  abortController.value.abort()
  state.value = 'stopping'
  // Partial response preserved
  abortController.value = null
}

// On completed/failed:
abortController.value = null

// On reconnecting:
// Abort old controller, create new one for retry
abortController.value?.abort()
abortController.value = new AbortController()
```

### Stream Token Generation

| Event Type | Description | State Transition |
|------------|-------------|-----------------|
| `phase.connecting` | Connection established, runId assigned | submitting → streaming |
| `phase.thinking` | AI in thinking mode, `[THINK]` tags may appear | streaming (sub-state) |
| `phase.answering` | AI generating answer | streaming (sub-state) |
| `token.stream` | Token chunk received, append to message | streaming (accumulate) |
| `tool.call` | MCP tool invocation started | streaming (sub-state) |
| `tool.result` | Tool execution result returned | streaming (sub-state) |
| `capability.end` | Stream complete, final response | streaming → completed |
| `capability.error` | Error during stream | streaming → failed |

```typescript
// Token accumulation during streaming
const currentResponse = ref<string>('')
const tokensReceived = ref<number>(0)

// On token.stream event:
currentResponse.value += event.data // Append token
tokensReceived.value++

// On capability.end:
// Response is complete, render action buttons
state.value = 'completed'

// On capability.error:
// Show error message, enable retry
state.value = 'failed'
errorMessage.value = event.data.message
```

## State Transitions (Detailed)

### welcome → submitting

**Trigger**: User submits first message (click send or Enter)

**Actions**:
1. Generate new `AbortController`
2. Set `threadId = null` (will be assigned by backend)
3. Set `runId = null` (will be assigned by SSE)
4. Disable input, show "发送中..." indicator
5. Add user message to local message list (optimistic)
6. Start HTTP POST to `/api/chat/stream`

**API Request**:
```typescript
POST /api/chat/stream
Headers: { Authorization: Bearer <token>, Content-Type: application/json }
Body: { 
  message: string, 
  agentId: string, 
  mode: 'flash' | 'pro' | 'thinking',
  threadId: null  // First message
}
Response: NDJSON stream
```

### submitting → streaming

**Trigger**: HTTP 200 received, NDJSON stream begins

**Actions**:
1. Receive `phase.connecting` event → assign `runId`
2. Create AI message placeholder in message list
3. Start progressive token accumulation
4. State indicator changes to streaming

**SSE Events**:
```json
{"type": "phase.connecting", "task_id": "run_abc123", "capability": "chat"}
{"type": "phase.thinking", "task_id": "run_abc123"}
{"type": "token.stream", "data": "[THINK]Analyzing..."}
{"type": "token.stream", "data": "Your net worth is..."}
```

### streaming → completed

**Trigger**: `capability.end` event received

**Actions**:
1. Finalize AI message content
2. Render action buttons (复制, 重新生成, 有帮助/没帮助)
3. Clear `AbortController`
4. Enable input
5. Update `threadId` in URL if first message
6. Scroll to bottom of messages

**SSE Event**:
```json
{"type": "capability.end", "task_id": "run_abc123"}
```

### streaming → stopping

**Trigger**: User clicks stop/cancel button during streaming

**Actions**:
1. Call `abortController.abort()`
2. Preserve partial response in message list
3. Clear `AbortController`
4. Enable input
5. Show "Response stopped" indicator

**Implementation**:
```typescript
const stopStream = () => {
  if (abortController.value && state.value === 'streaming') {
    abortController.value.abort()
    state.value = 'stopping'
    abortController.value = null
    // Partial response preserved, input re-enabled
    inputDisabled.value = false
  }
}
```

### streaming → failed

**Trigger**: HTTP error, SSE error, or `capability.error` event

**Actions**:
1. Show error message ("AI 服务暂时不可用")
2. Clear `AbortController`
3. Enable input
4. Show retry button

**Error Types**:
| Error | Message | Recovery |
|-------|---------|----------|
| HTTP 5xx | "服务器错误" | Retry button |
| HTTP 401 | Auth expired | Redirect to login |
| SSE close | "连接中断" | Auto reconnect (reconnecting state) |
| SSE error | "AI 服务暂时不可用" | Retry button |
| `capability.error` | Custom error message | Retry/regenerate |

### streaming → reconnecting

**Trigger**: SSE connection lost during streaming (not user-initiated)

**Actions**:
1. Preserve partial response and state
2. Show "正在重连..." indicator
3. Create new `AbortController`
4. Retry SSE connection (max 3 retries)
5. On success: continue streaming
6. On failure: → failed state

**Reconnect Logic**:
```typescript
const reconnectAttempts = ref<number>(0)
const MAX_RECONNECTS = 3

const handleSSEDisconnect = () => {
  if (reconnectAttempts.value < MAX_RECONNECTS) {
    state.value = 'reconnecting'
    reconnectAttempts.value++
    // Retry SSE connection
    abortController.value = new AbortController()
    // Reconnect with same threadId/runId
  } else {
    state.value = 'failed'
    errorMessage.value = '连接中断，请重试'
  }
}
```

### completed → idle

**Trigger**: Stream complete, response rendered

**Actions**:
1. Input placeholder changes to "继续对话..."
2. Input enabled
3. Action buttons visible on last AI message
4. Ready for next message submission

**State Variables**:
- `threadId`: Set (persisted in URL)
- `runId`: Preserved for regenerate reference
- `AbortController`: null

### idle → submitting

**Trigger**: User submits next message in existing session

**Actions**:
1. Generate new `AbortController`
2. Keep existing `threadId`
3. Reset `runId = null` (new run)
4. Disable input, show "发送中..."
5. Add user message to list
6. Start HTTP POST with `threadId`

**API Request**:
```typescript
POST /api/chat/stream
Body: { 
  message: string, 
  agentId: string, 
  mode: 'flash' | 'pro' | 'thinking',
  threadId: 'xxx'  // Existing session
}
```

### failed → submitting (Retry)

**Trigger**: User clicks retry button

**Actions**:
1. Clear error message
2. Generate new `AbortController`
3. Re-submit same message
4. Same `threadId` if exists

## UI Component Mapping by State

### Numina Components

| State | Key Components | Props/State |
|-------|---------------|-------------|
| welcome | `WelcomePrompt`, `CategoryButtons` | suggestions, categories, agentInfo |
| idle | `InputBox`, `MessageList` | placeholder="继续对话...", disabled=false |
| submitting | `InputBox`, `MessageList`, `StatusIndicator` | disabled=true, status="发送中" |
| streaming | `MessageList`, `StreamingIndicator` | streaming=true, partial response |
| stopping | `MessageList`, `InputBox` | partial response, disabled=false |
| completed | `MessageList`, `ActionButtons`, `InputBox` | actions=[copy,regenerate,feedback] |

| stopping | `PartialMessage` | preserved partial |
| completed | `MessageContent`, `SuggestionsPanel` | actions, suggestions |
| failed | `ErrorBanner`, `RetryButton` | error display |
| reconnecting | `ReconnectStatus` | reconnect indicator |

## Event Types (NDJSON Protocol)

### Numina NDJSON Events

```typescript
interface StreamEvent {
  type: 'phase.connecting' | 'phase.thinking' | 'phase.answering' | 
        'token.stream' | 'tool.call' | 'tool.result' | 
        'capability.end' | 'capability.error';
  task_id: string;  // This is the runId
  capability: string;
  data?: any;
}

// Event sequence example:
{"type": "phase.connecting", "task_id": "run_abc123", "capability": "chat"}
{"type": "phase.thinking", "task_id": "run_abc123"}
{"type": "token.stream", "data": "[THINK]Analyzing your question..."}
{"type": "phase.answering", "task_id": "run_abc123"}
{"type": "token.stream", "data": "根据您的数据..."}
{"type": "tool.call", "data": {"tool": "mcp_calculator", "args": {...}}}
{"type": "tool.result", "data": {"result": 12345}}
{"type": "token.stream", "data": "您的净资产约为 12345 元"}
{"type": "capability.end", "task_id": "run_abc123"}
```

### Event → State Mapping

| Event | Current State | Next State | Actions |
|-------|--------------|------------|---------|
| `phase.connecting` | submitting | streaming | assign runId |
| `phase.thinking` | streaming | streaming (thinking) | show thinking indicator |
| `phase.answering` | streaming | streaming (answering) | hide thinking, start text |
| `token.stream` | streaming | streaming | append token to response |
| `tool.call` | streaming | streaming (tool) | render tool card |
| `tool.result` | streaming | streaming (tool) | update tool card with result |
| `capability.end` | streaming | completed | finalize response |
| `capability.error` | streaming | failed | show error |

## Error Codes

| Code | Message | State Transition | Recovery |
|------|---------|-----------------|----------|
| `chat_stream_error` | "AI 服务暂时不可用" | streaming → failed | Retry button |
| `agent_not_found` | "智能体不存在" | welcome → failed | Navigate to AI Hub |
| `model_not_available` | "未找到匹配的模型" | idle → failed | Configure tenant AI |
| `auth_expired` | Auth token expired | any → redirect | Re-login |
| `sse_disconnect` | "连接中断" | streaming → reconnecting | Auto reconnect |
| `sse_timeout` | "连接超时" | streaming → failed | Retry button |
