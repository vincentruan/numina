# Numina Family Manifesto — 角色感知体验哲学

> **状态**：v1.2 — 拆分为三文档架构
> **日期**：2026-07-30
> **范围**：main app (Together AI) + child app (Clay) 跨端体验原则
> **目的**：为 Numina 的三个家庭角色定义体验哲学和情感设计边界
>
> **本文档是愿景+原则层**。交互规范详见 [`family-interaction-rules.md`](./design/family-interaction-rules.md)，遗留目标整合详见 [`family-manifesto-deferred-items.md`](./design/family-manifesto-deferred-items.md)。

---

## 1. 愿景

Numina 是一个**家庭共用的**财务工具，但它服务的不是"一个用户"，而是**一个家庭生态**。

家长管理资产时感到掌控，成员参与日常时感到被尊重，孩子完成任务时感到被庆祝——这三种情感不是附加功能，而是产品存在的理由。

**核心信念**：好的家庭工具应该让每个角色都觉得自己是家庭故事中重要的一环，而不是旁观者。

## 2. 角色画像

### 2.1 Owner — 家庭守护者

| 维度 | 描述 |
|------|------|
| **身份** | 家庭创建者，拥有最终决策权 |
| **核心情感** | 掌控 + 责任 |
| **焦虑源** | 数据安全、隐私泄漏、设置影响全家 |
| **使用模式** | 低频高价值 — 设置配置、审批请求、查看报表 |
| **技术素养** | 中高，能理解配置项含义 |
| **交互期望** | 每个操作都应该让人确信"我知道这会影响什么" |

**设计承诺**：
- 设置页的每个配置项都应有"影响说明"（改变这个值会如何影响家人看到的体验）
- 破坏性操作需要"暂停设计" — 慢动画、二次确认、影响预览
- Shimmer/Loading 传达"正在整理全家数据"的秩序感

### 2.2 Member — 家庭参与者

| 维度 | 描述 |
|------|------|
| **身份** | 加入家庭的成人成员，有完整的数据管理权但无管理权 |
| **核心情感** | 参与 + 效率 |
| **焦虑源** | 被排除在外、操作受限、无法表达偏好 |
| **使用模式** | 中频日常 — 查看财务、记录资产、使用 AI 建议 |
| **技术素养** | 中等，需要引导但不需要"被教" |
| **交互期望** | "我是家庭的一部分，不只是一个被管理的数据源" |

**设计承诺**：
- 个人偏好（视图、通知频率、趋势周期）应有表达空间
- 被 owner 设置影响的项应该有"为什么是这样"的透明解释
- 与 owner 看到相同质量的数据可视化，不因角色降级

### 2.3 Child — 家庭小学者

| 维度 | 描述 |
|------|------|
| **身份** | 家庭中的孩子（4-12岁），通过独立 app 使用 |
| **核心情感** | 成就感 + 安全感 |
| **焦虑源** | 做错事被惩罚感、等待太久失去兴趣、不理解"为什么不行" |
| **使用模式** | 高频日常 — 完成任务、查看心愿、收集奖励 |
| **技术素养** | 低，纯视觉交互 |
| **交互期望** | "每次打开都有惊喜，每次完成都被认可" |

**设计承诺**：
- 完成任何任务都应该有可感知的正向视觉反馈
- 错误和拒绝应该被"去惩罚化" — 不用弹窗，用温和的 inline 提示
- 不应让未完成的任务产生"我在落后"的焦虑感

## 3. 四条核心设计原则

### P1. 掌控不焦虑 (Control without Anxiety)

> 权力应该让人感到安心，而不是紧张。

**具体规则**：
- 设置页的 shimmer 时长 600ms，逐行展开，传达"正在整理你的数据"
- Owner 看到配置变更时，显示"影响范围"提示（"此设置影响全家 X 人的 AI 建议缓存时长"）
- 破坏性操作（删除成员、重置密码）使用底部 slide-up 面板，不用中心弹窗
- 暂停设计采用方案 A：不延迟按钮，靠 bottom-sheet 慢入动画 + "影响预览"文案创造停顿

### P2. 参与不旁观 (Participation without Spectating)

> 每个家庭成员都应该觉得"这个工具也有我的声音"。

**具体规则**：
- Member 的 UserConfigPage 应该与 Owner 的 FamilyConfigPage 有对等的视觉质量
- 当 owner 的设置影响了 member 的体验，应在对应页面显示一行说明
- Member 看到的 AI 建议不应被降级 — 与 owner 看到同等质量的分析
- 通知策略：使用 Vant 4 `van-notify` 顶部通知条，不做独立偏好设置页

### P3. 成就不压力 (Achievement without Pressure)

> 庆祝完成，但不让未完成成为负担。

**具体规则**：
- 任务完成的 celebration 动画 ≤ 1.5s（兴奋但不打断节奏）
- 未完成的任务不应该在首页用红色/警告色强调，用温和的"等你回来"语气
- 变率强化（mystery bonus ~20%）全年龄段统一，未触发时给安慰替代文案（"下次一定！"）
- 连续未登录不应显示"你已经 X 天没来了"的 guilt-trip 提示

### P4. 暂停即尊重 (Pause is Respect)

> 涉及钱、家庭、破坏的操作，交互应该主动创造思考空间。

**具体规则**：
- 财务决策弹窗使用半屏 bottom-sheet + 200ms 慢入动画（不是瞬间弹出的 dialog）
- 删除资产/负债的确认面板需要展示"删除后失去什么"（数据、历史记录、关联的心愿链接）
- 家庭设置变更显示"变更预览"（"如果开启，你的家人会看到..."）
- 不可逆操作使用红色强调

### ~~P5. 声音可选，振动克制~~ → 未来可能设计

> ⚠️ **移出核心原则**：Numina 是 H5 应用，`navigator.vibrate()` 和 Web Audio API 在移动端浏览器兼容性有限。保留为未来原生 app 或 PWA 增强时的参考。
>
> **未来参考**：所有音效必须可关闭 / Haptic 仅里程碑触发 / 声音分三级（celebration/ambient/alert，alert 默认关闭）

## 5. 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 覆盖范围 | 全角色（Owner + Member + Child） | child app 交互设计缺失最严重 |
| Shimmer 差异化 | 按角色分 2 类（Owner/Member 共享，Child 独立） | 同 app 视觉一致，child 有独立 Clay 体系 |
| 弹窗分类 | 6 类（破坏性/审批/财务/成就/错误/信息） | 完整光谱覆盖 |
| 动画时长上限 | 2000ms 硬上限 | 超过 2s 造成"等待焦虑" |
| 变率强化 | V1 纳入，不关闭 | 全年龄段统一 20%，未触发给安慰文案 |
| 暂停设计 | 方案 A：不延迟按钮 | WCAG 合规，bottom-sheet 慢入已足够 |
| Shimmer 组件 | 可复用 RoleShimmer | main skeleton / child 品牌色脉动 |
| Member 通知 | van-notify 顶部通知条 | 轻量够用 |
| P5 声音/振动 | 移出核心原则 | H5 无可靠 API |
