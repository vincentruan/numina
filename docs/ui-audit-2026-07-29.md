## Fixes Applied

### P0 — Child PIN Login Browser Failure ✅ FIXED
**Root Cause**: Backend uses SQLite (root `.env` has higher precedence than `server/.env`), not PostgreSQL. All PIN updates were being applied to the wrong database.

**Files Changed**:
- `server/packages/core/settings.py` — Documented .env precedence
- `server/packages/db/session.py` — Added `engine.dispose()` in `get_db()` to prevent stale connection pool reads
- `server/packages/db/engine.py` — Added `pool_reset_on_return: "rollback"` for PostgreSQL

**Skill Files Updated**:
- `.claude/skills/numina-sim-test/test-cases/_common.md` — Corrected PIN from `🐰🥕🌈⭐` to `🐱🐶🌟🌈`, added browser encoding issue documentation
- `.claude/skills/numina-sim-test/test-cases/groups/g3-child/area1-child.md` — Corrected PIN references
- `.claude/skills/numina-sim-test/SKILL.md` — Corrected all PIN references

### P1 — Session Expires Too Quickly ✅ FIXED
**Root Cause**: Access token TTL was 15 minutes, too short for testing.

**Files Changed**:
- `server/packages/core/settings.py` — Increased `ACCESS_TOKEN_EXPIRE_MINUTES` from 15 to 60
- `server/apps/backend/app/auth/cookies.py` — Added `domain="localhost"` for dev mode cookies to enable cross-port session sharing (5173 ↔ 5174)

### P2 — Calendar "5" Markers ⚠️ BY DESIGN
The "5" markers on calendar dates are activity count badges (e.g., 5 chores on that day). This is working as designed — the visual design could be improved to make it clearer these are counts, not duplicate dates, but it's not a bug.

### P2 — Favicon Path ⚠️ NOT A BUG
The child favicon paths in `index.html` are correct (`/child/favicon.svg`). The apparent double `/child/child/` prefix was only visible in the Vite dev server's transformed HTML, not the source.

### P3 — Child Greeting Uses "小探险家" Instead of Actual Name ✅ FIXED
**Root Cause**: 
1. Router guard used `authStore.fetchMe()` (adult endpoint `/auth/me`) instead of `authStore.fetchChildMe()` (child endpoint `/auth/child/me`)
2. `fetchChildMe()` didn't populate `authStore.user`
3. Home page read from `childAuthStore.childUser` which was never populated by the router guard

**Files Changed**:
- `frontend/apps/child/src/router/index.ts` — Changed `fetchMe()` → `fetchChildMe()`, populate `childAuthStore.childUser` in guard
- `frontend/packages/auth/src/stores/auth.ts` — `fetchChildMe()` now populates `user.value` and localStorage
- `frontend/apps/child/src/pages/ChildHomePage.vue` — Changed greeting to use `authStore.user?.display_name`

## Key Lessons Learned

1. **Database Configuration**: The project has two `.env` files with different DATABASE_URL values. Root `.env` has higher precedence than `server/.env`. Always verify which database the backend actually uses.

2. **Cookie Scoping in Dev Mode**: When frontend apps run on different ports (5173, 5174), cookies must be set with `domain="localhost"` to be shared across ports.

3. **Child Auth Flow**: The child app uses separate auth cookies (`child_access_token`) and endpoint (`/auth/child/me`). The router guard must use the child-specific endpoint.

4. **Connection Pool Staleness**: SQLAlchemy connection pools can cache stale data. Adding `engine.dispose()` in `get_db()` ensures fresh reads after external updates.
