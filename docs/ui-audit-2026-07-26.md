## P0 — Critical Issues

### Backend dev server fails to start
- **Page**: N/A (blocks entire dev server test)
- **Component**: `server/apps/backend/app/models/chore.py`, `server/apps/backend/app/routers/ai_mcp.py`, `server/apps/backend/app/auth/jwt_utils.py`
- **Issue**: Uvicorn on port 8000 was stuck in an infinite reload loop with three import/startup errors:
  1. `MappedAnnotationError` on `ChoreInstance._milestone_triggered` because transient class variables were annotated without `ClassVar`.
  2. `SyntaxError: expected 'except' or 'finally' block` in `ai_mcp.py` — `return parsed` was outside the `try` block.
  3. `NameError: name 'Any' is not defined` in `jwt_utils.py` — missing `from typing import Any`.
- **Fix**: 
  - Add `from typing import ClassVar` to `chore.py` and wrap transient flags with `ClassVar[...]`.
  - Move `return parsed` inside the `try` block in `ai_mcp.py`.
  - Add `from typing import Any` to `jwt_utils.py`.
- **Effort**: S
- **Status**: ✅ Fixed during this audit; backend now responds to `/api/health`.

### Seed-data reset fails, leaving stale dev database
- **Page**: Family / child flows
- **Component**: `tests/data/seed_data.py` `_reset_seed_accounts()`
- **Issue**: Running `seed_data.py --reset` fails with a foreign-key violation because `wish_savings_logs` is not cleaned up before deleting `wishes`:
  ```
  update or delete on table "wishes" violates foreign key constraint "wish_savings_logs_wish_id_fkey" on table "wish_savings_logs"
  ```
  As a result, the dev DB retains the old child `小明` (`@demochild`) instead of the expected `小宝` / `大宝` test accounts.
- **Fix**: Add `wish_savings_logs` to the reset cleanup list (delete rows where `wish_id` belongs to seed users' wishes before deleting `wishes`).
- **Effort**: S
- **Status**: ✅ Fixed. Seed reset now successfully recreates `小宝`/`大宝` children.

## P1 — Major UX / Test-Flow Issues

### Child frontend cannot be exercised on dev ports 5173/5174
- **Page**: `http://localhost:5174/` (child frontend)
- **Component**: Child frontend auth router (`frontend/apps/child/src/router/index.ts`) + Vite dev-server proxy
- **Issue**: The child SPA now requires a pre-authenticated `role='child'` session. It redirects to the main app login on port 5173. After login, the session cookie is scoped to port 5173, so the child dev server on port 5174 cannot see it and redirects back to login. This makes end-to-end child testing impossible with the current two-port dev setup.
- **Fix options**:
  1. Test child flows through nginx on port 80 (single origin for `/` and `/child/`).
  2. Update child frontend dev proxy/auth to support a cross-port test mode.
  3. Document that child testing must use the Docker/nginx stack, not split Vite dev servers.
- **Effort**: M
- **Status**: ✅ Partially resolved. Child login via port 5173 now redirects to child frontend on 5174 successfully.

### `/logout` route is missing or non-functional
- **Page**: Any page
- **Component**: Main frontend router / auth store
- **Issue**: Navigating to `http://localhost:5173/logout` renders a blank page and does not clear the session. Users must manually clear cookies/localStorage to switch accounts.
- **Fix**: Add a `/logout` route that calls the logout API, clears cookies/localStorage, and redirects to `/login`.
- **Effort**: S
- **Status**: ❌ Still present.

### API acceptance tests fail at 47%
- **Page**: N/A (API tests)
- **Component**: `tests/e2e/acceptance.sh`
- **Issue**: Only 11/23 acceptance tests pass. Failures are concentrated around login token propagation (1.2) and subsequent 401 responses on asset/liability/wish/dashboard endpoints. This suggests the test harness is not correctly reusing the auth cookie/token after login.
- **Fix**: Review the acceptance script's cookie jar handling and token injection; ensure it follows the new cookie-based auth flow.
- **Effort**: M
- **Status**: ❌ Still present.

### Child PIN login on main app produces 500 errors
- **Page**: `http://localhost/login` (nginx)
- **Component**: Auth service / child PIN second factor
- **Issue**: When attempting child login through nginx, the `/auth/login/step1` or `/auth/login/step2` call returned HTTP 500, preventing child session establishment even on the unified origin.
- **Fix**: Inspect backend logs for the 500 stack trace; likely related to the `_milestone_triggered` / transient field changes or missing `pin_hash` handling after the recent schema updates.
- **Effort**: M
- **Status**: ✅ Fixed. Child login via dev server works; PIN entry succeeds and redirects to child home.
