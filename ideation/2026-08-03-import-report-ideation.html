Ideation

Import-Report 多格式智能导入

将导入功能从设置迁移至财务模块，扩展支持截图和 Excel 文件的 AI 识别导入，并提供交互式预览编辑界面。

📅 2026-08-03 🏗️ repo-grounded 📊 40 raw → 7 survivors

Grounding Context

Codebase 现状

  • 导入页当前路由 /settings/import-report
  • 组件 ImportReportPage.vue，仅接受 PDF
  • 后端 /api/v1/import/parse-pdf 同步调用 agent
  • Agent import-parse 是第 3 个 stream_run agent
  • MCP 批量写入工具已存在但未接入导入流程
  • 视觉管线 (U11) 已支持扫描件 PDF→PNG→vision
  • AI chat 已接受多格式文件（PDF/Excel/图片）做分析

外部调研

  • 无主流消费级金融 App 使用 LLM-vision 做文档解析
  • 截图→数据最佳实践：多模态 LLM + 结构化输出 schema
  • Excel 导入标准 UX：上传→映射列→预览（YNAB 模式）
  • 预览 UX：分屏、置信度着色、行内编辑
  • URL 建议：/import 作为顶级路由
  • 成本策略：轻量模型优先，低置信时升级

数据模型

  • Asset: name, type, value, currency, purchase details, institution
  • Liability: name, amounts, rates, dates, institution
  • Wish: name, price, priority, savings progress
  • 当前 confirm 端点仅创建 Asset，不覆盖 Liability/Wish

关键约束

  • 隐私优先、自托管家庭系统
  • 所有 UI 文案必须 i18n
  • 错误信息用中文
  • 财务路由已组织在 /finance

1

统一文档摄入管线 + 草稿暂存

构建单一摄入管线，接受任何文档类型（PDF、截图、Excel），通过共享的 extract → stage → review → commit 流程处理。引入 draft_imports 暂存表，状态为 pending 的记录不触碰真实 Asset/Liability 表，直到用户确认。将 /confirm-via-agent 设为默认确认路径，利用已有的 MCP 批量写入工具（import_assets_batch、import_liabilities_batch）实现原子性批量提交和逐行错误报告。

任意文件 → 格式检测+提取 → draft_imports 暂存 → 预览/编辑 → 确认 → MCP batch write
Axis
多格式摄入 + 预览确认 UX
Basis
direct: 代码库已有 3 个 MCP batch-write 工具和视觉管线，但未在导入流程中使用；现有 confirm 端点直接写 DB，无逐行错误报告
Rationale
最高杠杆基础架构。一旦暂存层存在，每个新数据源只需一个适配器，不需要新的审核流程。复利效应：导入、对账、重复检测、手动修正都成为同一 draft_imports 表上的操作
Downsides
需要新增 draft_imports 表和 alembic migration；确认流程需重构为两阶段

2

路由重组：迁移至 /finance/import

将导入页面从 /settings/import-report 迁移至 /finance/import，使 /finance 成为数据操作中枢。在 FinanceHubPage 页头添加"导入"操作按钮（非 tab——它是单次向导，不是持久列表），保持 hub 整洁同时让导入在用户思考数据的地方可发现。旧 URL 设置 301 重定向保持向后兼容。

Axis
路由组织
Basis
direct: router/index.ts 将 ImportReport 嵌套在 settings 下，与密码更改、设备管理并列——这些是设置关注点，不是金融数据摄入
Rationale
路由结构是一扇单向门。当导入获得截图和 Excel 支持后，它将成为主要的数据摄入界面。在功能扩展前先建立正确的信息架构，避免后续二次重构。同时为 reconcile、export 等未来数据操作预留自然位置
Downsides
需要更新所有指向旧路由的导航链接和文档；需处理 deep link 兼容
Confidence
95%
Complexity
Low
3

零摩擦捕捉：剪贴板粘贴 + 截图直传

反转上传模型：页面监听 Ctrl+V 粘贴事件，直接从剪贴板提取图片 blob 发送到视觉管线。PDF 变为次要的"或选择文件"路径。用户在京东/淘宝截图后，Ctrl+V 粘贴即触发识别——无需文件选择器对话框，1 步完成输入。后端统一 /import/parse 端点接受 pdf, png, jpg, xlsx, xls, csv，服务端自动检测格式并路由到对应提取策略。

Axis
多格式摄入
Basis
reasoned: 当前流程需要 4 步（按钮→文件选择器→导航→选择），而用户往往刚截完图。剪贴板粘贴将操作缩减为 1 步。视觉管线 (U11) 已原生处理图片，后端仅需在上传处理器中增加 image/* 支持
Rationale
电商截图是家庭资产追踪中最高频、最痛苦的输入源。当前每次京东订单都需手动录入——这个摩擦点正是此功能要消除的。做对了会让产品感觉"有魔力"
Downsides
需要平台特定的提取提示（京东/淘宝/Amazon 布局不同）；移动端粘贴支持有限
Confidence
85%
Complexity
Medium
4

交互式预览 + 字段级置信度可视化

扩展预览页从"只读确认"到"完整编辑界面"。每行显示置信度着色：绿色=高置信（AI 精确匹配）、黄色=需审查（模糊匹配或缺失值）、红色=需编辑。用户可修改 asset_type、从 21 个系统类别中选择 category、切换 currency、切换 create/update action，或删除不需要的行。支持按 target_type 分组（asset/liability/wish），使用 van-picker 组件。

Axis
预览确认 UX
Basis
direct: ImportPreviewItem schema 返回 asset_type, category_hint, currency, quantity——但前端预览仅为 name 和 current_value 渲染可编辑字段，其余字段不可变
Rationale
截图和 Excel 引入比银行对账单 PDF 更多的解析不确定性。预览页是用户建立信任的主要界面。如果用户无法修正错误分类的资产或纠正误读的价格，他们会失去对 AI 导入数据的信任并退回手动录入。编辑界面必须匹配输入的不确定性
Downsides
前端开发量较大；需要为每个字段类型实现合适的编辑组件
Confidence
90%
Complexity

5

AI 驱动的万能表格识别（无列映射向导）

跳过传统 Excel 导入的列映射步骤。将表格数据作为结构化文本（逐行 JSON）发送给 import-parse agent，让 LLM 在上下文中推断列语义（"A 列是资产名称、C 列是金额、D 列是日期"）。系统通过 ImportTemplate 模型记住该文件的列模式，下次上传同格式文件时跳过 AI 推断直接按已知映射解析——将向导从"每次痛苦"变为"一次痛苦"。

Axis
多格式摄入 + AI 识别管线
Basis
reasoned: LLM 擅长这种结构推断。给定 50 行 {A: '招商银行', B: 150000, C: 'CNY'}，模型立即识别 B 为 value、A 为 institution。当前 agent 已处理 PDF 的自由文本，表格行作为 JSON-lines 在结构上更简单
Rationale
消除了传统 Excel 导入的 3 步向导，降低用户认知负担。模板记忆创造复利——从同一银行第 5 次导入时几乎零摩擦。这对自托管家庭应用尤其强大，因为同一家庭反复从相同来源导入
Downsides
LLM 对非标准格式的推断可能出错；需要 fallback 到手动映射
Confidence
80%
Complexity
Medium
6

流式渐进解析

对大型 PDF（10+ 页银行对账单）或多文件批量上传，改为流式解析：AI 每解析完一页/一个文件就立即推送预览卡片，用户可以在全部解析完成前开始审查和确认已解析部分。后端利用现有 SSE 管线（stream_run 协议），让 import-parse agent 每处理完一页就发布增量结果事件。用户从"等 2 分钟看白屏"变为"每 10 秒看到新内容"。

Axis
AI 识别管线 + 预览确认 UX
Basis
direct: 当前后端有 120s 超时（agent 有 110s 内部超时），用户可能等待长达 2 分钟无任何反馈。stream_run 基础设施已支持 SSE——但 parse-pdf 端点是同步 JSON
Rationale
2 分钟的加载转圈是"感觉坏了"的 UX 定义——用户会刷新页面中断解析。流式预览将感知等待时间从 O(n) 降至 O(1)。这对截图/Excel 输入更重要，因为它们可能产出更多条目、耗时更长
Downsides
需要将 parse 端点从同步 JSON 转为 SSE；前端需支持增量渲染
Confidence
75%
Complexity
High
7

自动提交 + 时间窗撤销

取消预览确认步骤的替代方案：AI 解析完成后直接写入数据库，同时在 Dashboard 展示"最近导入"卡片，列出本次导入的所有条目，附带 60 秒倒计时撤销按钮。超时后条目仍可逐条修改/删除，但批量撤销窗口关闭。新增 import_batch 表记录每次导入的条目 ID 列表，支持按 batch 回滚。

Axis
预览确认 UX
Basis
reasoned: 对于高频用户（每周导入银行账单），80% 的情况 AI 识别准确，预览步骤变成纯粹的点击疲劳。类似 email 的 undo-send 模式——安全网存在但不增加大多数场景的操作成本
Rationale
将导入从 3 步减到 1 步。对已建立信任的老用户，预览是纯摩擦。可与 Idea #4 共存：默认展示预览，但允许用户开启"自动提交"模式跳过确认
Downsides
新用户可能困惑于数据"自动出现"；需要 batch 回滚基础设施；误操作风险
Confidence
70%
Complexity
Medium
